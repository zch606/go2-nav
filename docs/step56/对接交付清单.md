## 这次对接的核心接口

你们只要对齐下面这些话题和消息就行：

- 输入给我这边的：`/global_path`、`/odometry/filtered`、`/imu/data`、`/terrain_cost`
- 我这边输出给他接的：`/cmd_vel`、`/safety_state`、`/motion_command`

消息定义都在 [src/dog_nav_interfaces/msg/](src/dog_nav_interfaces/msg) 里，重点是：
- [DogMotion.msg](src/dog_nav_interfaces/msg/DogMotion.msg)
- [SafetyState.msg](src/dog_nav_interfaces/msg/SafetyState.msg)

## 环境和依赖

这个部分要说明清楚，但不用单独打包 ROS 环境。

### 运行环境
- Ubuntu 22.04
- ROS 2 Humble
- Python 3
- `colcon`

### 需要有的 ROS 依赖
这些已经体现在包的 `package.xml` 里，对方本机最好先装好：
- `rclpy`
- `geometry_msgs`
- `nav_msgs`
- `sensor_msgs`
- `std_msgs`
- `launch`
- `launch_ros`
- `ament_index_python`

### 编译方式
让对方在自己的工作区里按下面顺序做：
1. `source /opt/ros/humble/setup.bash`
2. `colcon build --packages-select dog_nav_interfaces dog_nav_step56`
3. `source install/setup.bash`

## 这两个包各自负责什么

### `dog_nav_interfaces`
只负责定义消息格式，不负责业务逻辑。

### `dog_nav_step56`
负责步骤 5-6 的节点逻辑，包括：
- 局部控制
- 安全监督
- 动作适配
- 模拟输入
- 测试记录

## 运行时怎么配合

如果他那边已经有上游数据，就把上游话题接到我这边需要的输入上即可。如果还没有真实数据，也可以先用模拟输入跑通闭环，确认下面这些话题能正常流动：

- `/global_path`
- `/odometry/filtered`
- `/imu/data`
- `/terrain_cost`
- `/cmd_vel`
- `/safety_state`
- `/motion_command`
