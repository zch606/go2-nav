# 导航可视化技术选型分析

> 需求：2.5D 地形 / 全局路径 / 起终点 三类可视化，统一方案，组员零学习成本。
>
> 结论：**全用 RViz2**，新增 1 个 publisher + 1 个 rviz 配置文件，总代码量 ~70 行。

---

## 零、先澄清术语

"> **`/local_terrain`** 和 **`/terrain_mesh`** 是两个不同的东西，文档里容易混用：

| 话题 | 消息类型 | 本质 | RViz2 能直接看吗 |
|:--|:--|:--|:--:|
| `/local_terrain` | `sensor_msgs/Image` (32FC1) | **2D 俯视热力图** — 从上往下看的一张灰度图，每个像素值=高度 | ✅ 能，但只有俯视视角，不能旋转看起伏 |
| `/terrain_mesh` | `visualization_msgs/Marker` (TRIANGLE_LIST) | **2.5D 三角形网** — 真正有高度的三维表面，可以旋转 | ✅ 能，3D 视角看地形起伏 |

**当前代码只发了 `/local_terrain`（2D），缺 `/terrain_mesh`（2.5D）。本文档的目标就是补上 `/terrain_mesh`。**

## 一、三类可视化分别需要什么

### 1.1 2.5D 地形图（本次重点）

```
数据源: 80×60 高程栅格 (stereo_terrain_node 已在内存中持有 grid)
需求:   RViz2 里旋转/缩放看地形起伏，颜色映射高度

       ┌─┬─┬─┬─┐
       │·│·│▄│·│  ← 红=高(障碍), 蓝=低(地面)
       ├─┼─┼─┼─┤
       │·│·│·│·│
```

**做法：** 把 80×60 栅格的每 2×2 邻格 → 2 个彩色三角形 → `visualization_msgs/Marker(TRIANGLE_LIST)` → RViz2 渲染。

```
80×60 栅格 → 79×59×2 = 9322 三角形 ≈ 28000 顶点
每帧生成耗时 < 1ms，5Hz 发布，RViz2 无压力
```

### 1.2 全局路径

```
数据: nav_msgs/Path (一串 (x, y) 路点)
做法: RViz2 自带的 Path 插件 — 订阅 /global_path，选颜色和线宽

    起点 ●────────────────→ ● 终点
```

> ⚠️ **坐标系必须和地形 Mesh 一致**（都用 `base_link` 或都用 `odom`），否则路径飘在地形上方几米处。

### 1.3 起点/终点标记

```
做法: visualization_msgs/Marker (SPHERE 类型)
      如果需要用户拖拽，用 InteractiveMarker

      🟢 起点               🔴 终点
```

## 二、坐标系对齐（最关键的前提条件）

**三个可视化必须共享同一个 `frame_id`，否则 RViz2 里各飘各的。**

```
当前项目坐标系:
  odom      — 里程计原点（世界固定）
  base_link — 机器人本体
  camera    — D435i 相机

数据各自用什么 frame ↘

  /terrain_mesh → base_link  (相机在机器人上，地形自机器人脚下展开)
  /global_path  → odom       (路径是世界坐标)
  /waypoints    → odom       (起终点是世界坐标)
```

**转换办法：** `base_link → odom` 的变换由 TF 广播（Go2 里程计节点自动发布）。RViz2 看到 frame_id 不同时会自动查 TF 变换对齐——**只要 TF 在运行，三个不同坐标系的显示层会自动叠在一起。** 不需要我们手动做任何转换。

验证命令（启动后在 RViz2 里确认）：
```bash
ros2 run tf2_tools view_frames   # 看 TF 树
```

如果 `odom → base_link` 这条边存在，说明坐标系对齐没问题。

## 四、方案选型：RViz2 一揽子

### 4.1 选择理由

1. **ROS2 自带** — Go2 和 VM 都预装，不用装任何东西
2. **一个窗口叠三层** — 地形 + 路径 + 标记共用一个 3D 视图
3. **组员零上手成本** — 群里有谁没用过 RViz2？
4. **标准工具链** — `visualization_msgs` + `sensor_msgs` 都是 ROS2 规范

### 4.2 需要写的代码

**改 1: `stereo_terrain_node.py` 新增 Mesh 发布者**（~55 行）

```python
# 新增 import
from visualization_msgs.msg import Marker
from geometry_msgs.msg import Point
from std_msgs.msg import ColorRGBA

def _height_to_color(z, z_min, z_max):
    """蓝(低) → 绿(中) → 红(高)"""
    t = max(0.0, min(1.0, (z - z_min) / (z_max - z_min)))
    return (t, 1.0 - abs(t - 0.5) * 2.0, 1.0 - t, 1.0)

def _grid_to_mesh(grid, grid_res, z_min, z_max, frame_id, stamp):
    """80×60高程栅格 → TRIANGLE_LIST Marker"""
    gh, gw = grid.shape
    half_w = gw // 2
    points, colors = [], []

    for r in range(gh - 1):
        for c in range(gw - 1):
            z00, z10 = grid[r, c],     grid[r, c + 1]
            z01, z11 = grid[r + 1, c], grid[r + 1, c + 1]
            if not any(np.isfinite(v) for v in [z00,z10,z01,z11]):
                continue
            zs = [v if np.isfinite(v) else 0.0 for v in [z00,z10,z01,z11]]
            y0, y1 = r * grid_res, (r + 1) * grid_res
            x0, x1 = (c - half_w) * grid_res, (c + 1 - half_w) * grid_res

            # 每格 2 个三角形 (左上+右上+左下, 右上+右下+左下)
            for tri in [(0,1,2),(1,3,2)]:
                for idx in tri:
                    pt = Point(x=float(x0 + (idx%2)*(x1-x0)),
                               y=float(y0 + (idx//2)*(y1-y0)),
                               z=float(zs[idx]))
                    points.append(pt)
                    r_c,g_c,b_c,a_c = _height_to_color(zs[idx],z_min,z_max)
                    colors.append(ColorRGBA(r=r_c,g=g_c,b=b_c,a=a_c))

    marker = Marker()
    marker.header.frame_id = frame_id      # 'base_link'
    marker.header.stamp = stamp
    marker.ns = 'terrain'
    marker.id = 0
    marker.type = Marker.TRIANGLE_LIST
    marker.action = Marker.ADD
    marker.scale.x = marker.scale.y = marker.scale.z = 1.0
    marker.points = points
    marker.colors = colors
    marker.pose.orientation.w = 1.0
    return marker
```

### 4.3 三个 level 的显示对比

| level | 话题 | RViz2 显示效果 | 何时用 |
|:--:|:--|:--|:--|
| 0 | `/local_terrain` (Image) | 2D 俯视灰度图，固定视角 | 快速验证数据到了没 |
| 1 | `/terrain_mesh` (Mesh) | 3D 可旋转地形，颜色=高度 | 调试地形检测准确性 |
| 2 | `/terrain_mesh` + `/global_path` | 地形上叠路径线 | 看路径是否踩着安全区域 |
| 3 | + `/waypoints` + RobotModel | 全要素：地形+路径+起点/终点+Go2模型 | 完整导航可视化 |

| 检查项 | 怎么看 | 期望 |
|:--|:--|:--|

| `/terrain_mesh` 有数据 | `ros2 topic echo /terrain_mesh --once` | 有点列表 |

### 5.4 常见问题

| 现象 | 原因 | 解决 |
|:--|:--|:--|
| RViz2 里地形不出现 | Fixed Frame 选错了 | 在 RViz2 左上角 Fixed Frame 下拉选 `base_link` |
| 地形位置偏了 | 相机高度/俯仰角不准 | 改 `stereo_terrain.yaml` 里 `cam_height`/`cam_pitch_deg` |
| 路径飘在地形上方 | 坐标系不一致 | 确认 TF 广播 odom→base_link |

## 八、性能预算

```
每帧数据量:
  9322 三角形 × 3 顶点 × 3 float + 颜色 = ~28000 顶点
                                          × (12B坐标 + 16B颜色)
                                          ≈ 0.8 MB/帧

5Hz 发布: 4 MB/s 网络带宽，Jetson/VM 均可承受
生成耗时: < 1ms (纯 NumPy 循环, 几十次 float 运算)
```
